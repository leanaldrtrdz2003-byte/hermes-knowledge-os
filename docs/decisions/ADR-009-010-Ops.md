# ADR-009 — Backups por capa (§34)
**Estado**: aceptado · **Fecha**: 2026-08-08

Backup = 3 capas coherentes:
1. **Control plane** → `pg_dump` (PostgreSQL completo: metadatos, claims,
   memoria, jobs).
2. **Objetos** → MinIO es inmutable y versionado; el backup real de objetos es
   periodico `mc mirror` al destino de respaldo.
3. **Vault/índices** → `tar` de `vault/` + `data/staging` + `data/lightrag`.

Restore: `make restore F=<backup.sql>` (recrea schema + datos; los índices
derivados se reconstruyen re-corriendo el pipeline incremental — no se
respaldan Qdrant "a ciegas", se reindexan, ver ADR-005).

# ADR-010 — Memoria del agente en PG (no en archivos)
**Estado**: aceptado · **Fecha**: 2026-08-08

La memoria de agente vive en `agent_memory` (PG) con tipos, importancia y
dedupe_key — NO en archivos del vault. El vault (05_MEMORY) es solo la vista
humana. Esto permite query (re) y filtrado por importancia sin tocar el FS,
y coexiste con la memoria nativa de Hermes (cada sistema es independiente).
